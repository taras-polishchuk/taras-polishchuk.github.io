2. СЕМЬ КРИТИЧНИХ ЗНАХІДОК VIKTORA (аналіз кожної)

Знахідка #1: alex-parts-prod — Coolify-abgeschnitten

Що:

"alex-parts-prod ist von Coolify abgeschnitten — Ping antwortet, aber Port 22 ist zu.
Der Kunde Lichtex läuft ungeprüft weiter und ist nicht deploybar."

Аналіз:

  • Hetzner server (178.104.77.165) був зареєстрований як Coolify slave для клієнта Lichtex
  • Сервер відповідає на ping (мережа жива)
  • SSH (port 22) закритий — Coolify не може deploy / manage
  • Клієнт працює (якщо сервіс не впаде, ніхто не дізнається)
  • Це SPOF для клієнта Lichtex + operational blind spot

Причина (можливі):

  • Hetzner firewall rules змінилися (outbound update)
  • Coolify agent (docker) зупинився
  • SSH key rotated без update в Coolify
  • Або просто OS update / reboot без recovery

Що робити (SA пріоритет):

  1. Immediate (1 год): Спробувати Hetzner Cloud Console → rescue mode → SSH fix
  2. Investigation (1 год): Чому SSH closed? Перевірити journalctl, sshd config
  3. Re-register (30 хв): Якщо треба — coolify server add повторно
  4. Runbook: "Slave disconnected" → автоматизований recovery через Hetzner API

Owner: Viktor (має Hetzner root access)

Severity: HIGH (операційна сліпота для paying customer)

Cost: €0 (Hetzner Cloud Console безкоштовно)

Що:

"Vier WordPress laufen am WP Toolkit vorbei (digilift.indyn.de, dms.indyn.de,
erechnung.indyn.de, new.klimadeluxe.de) — keine Auto-Updates, keine

  • Без auto-updates

  • Без backup через WP Toolkit (можуть мати file/db backup, але не WP-aware)
  • Виявлені тільки через ручну перевірку

  • WP встановлено поза Plesk доменом (можливо, окремий vhost)
  • Або перенесено з іншого серверу без WP Toolkit re-registration
  • WP Toolkit бачить тільки "managed" WP installations

Що робити:

  1. Register кожен в WP Toolkit (Plesk UI → WordPress → Scan)
  2. Setup auto-updates + backups
  3. Audit чи мають вони critical security issues
  4. Document як знахідку в Notion Rollen-und-Zugriffsdokumentation

Owner: Taras (з Viktor approval)

Severity: HIGH (security blind spots)

Знахідка #6: Cross-Dependency TalkHub License на ax1

Що:

"Eine Abhängigkeit quer über beide Welten: der TalkHub-Lizenzserver
lic.linkify.cloud liegt auf ax1. Fällt ax1 aus, trifft es auch den
zahlenden Kunden RAZERTECH auf Hetzner."

Аналіз:

  • lic.linkify.cloud = TalkHub license server (DNS: lic.linkify.cloud)
  • Hosted на ax1 (Plesk webhosting, 217.154.83.16)
  • TalkHub (на Hetzner slave srv-datq5) запитує license від ax1
  • Якщо ax1 впаде → RAZERTECH (paying customer) втратить service

Це КРИТИЧНИЙ архітектурний smell:

  • License сервер не повинен жити на webhosting (single Plesk instance)
  • Якщо Plesk reboot для maintenance → RAZERTECH down
  • Якщо backup restore ax1 → RAZERTECH down during restore

Що робити (3 варіанти):

Option A: Move license server to Coolify (рекомендую)

  • Deploy license server as Coolify app on master
  • HA через 2 instances (master + slave)
  • Backup через Coolify
  • Cost: 0 €

Option B: Move to separate VM

  • License сервер deserves own VM (micro instance, 1 vCPU / 512 MB RAM)
  • Hetzner Cloud: €4/month
  • Isolated, simple backup
  • Cost: €4/month

Option C: Make ax1 license server HA

  • Add secondary license server (also ax1 but different zone)
  • DNS failover
  • Cost: 0 € (manual) або €10/month (DNS failover service)

Рекомендую Option A. License server → Coolify app (simple container, 256 MB RAM), 2 instances.

Owner: Viktor (master Coolify access) + Taras (deployment)

Severity: HIGH (загрожує paying customer)

Cost: €0-4/month

Знахідка #7: srv-datq5 — knapp an Ressourcen

Що:

"srv-datq5 ist knapp: 2 vCPU / 3 GB RAM tragen zwei TalkHub-Instanzen plus
einen Drei-Container-Stack. Kein Puffer."

Аналіз:

  • Hetzner server srv-datq5 (178.104.142.147)
  • Resources: 2 vCPU / 3 GB RAM (per Viktor)
  • Workloads:

    • - 2 TalkHub instances (own + RAZERTECH)

    - 3-container stack (linkify-adc, Знахідка #5)

  • Zero buffer — будь-який spike = OOM killer

Причина:

  • Hetzner cheap plan (CX22 = €4/month or similar)
  • Multiple production workloads crammed in

Що робити:

Option A: Scale up (immediate, €10-15/month)

  • Hetzner CX32 (4 vCPU / 8 GB) — €15/month
  • Або CPX21 (3 vCPU / 4 GB) — €10/month (AMD)
  • Decision tree:

    • - if workloads growing → CX32

    - if workloads stable → CPX21

Option B: Move workloads to Proxmox cluster

  • 3-4 контейнери → Proxmox LXC (lightweight)
  • Звільнити srv-datq5
  • Cost: €0 (own infra)

Option C: Add second Hetzner slave

  • HA setup (2 slaves)
  • Coolify load balance
  • Cost: +€10-15/month

Рекомендую Option A + Option B (parallel).

  • Option A — immediate (1-2 год) для stability
  • Option B — medium-term (1-2 тижні) для cost optimization

Owner: Viktor (Hetzner root)

Severity: HIGH (zero buffer = OOM anytime)

Cost: €10-15/month
